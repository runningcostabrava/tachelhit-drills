# Tachelhit Drills — language documentation & learning platform

A community platform for **collecting Atlas Tamazight (Tachelhit) from people
and the internet, and learning it** — built around Catalan as the reference
language, with Arabic and Latin romanization alongside Tifinagh (ⵜⵉⴼⵉⵏⴰⵖ).

## What it does

**Capture** — turn any content into learning material:
- Paste a **YouTube / Instagram / TikTok / podcast URL** (or upload a
  video/audio file): the server downloads it, uses platform subtitles when
  available and Whisper ASR otherwise, and returns timestamped segments.
- **Song mode**: paste the lyrics and they are aligned onto the ASR
  timestamps (ASR hears sung vocals poorly but times them well).
- **OCR**: burned-in subtitles (Latin + Arabic scripts) read off video
  frames by a dedicated Space.
- **⚡ Auto mode**: one tap runs the whole chain server-side — transcribe →
  correct → translate (Catalan · Arabic · Tifinagh) → create drills with
  clipped media → optionally render a vertical reel per drill. Survives
  closing the page.

**Learn** — evidence-based practice:
- **🧠 Spaced repetition** (SM-2): per-user review queues; the home screen
  shows what's due.
- **Recall-first cards**: only the Catalan prompt shows/plays until you
  reveal; then native audio plays twice.
- **🎤 Pronunciation feedback**: record yourself; your speech is transcribed
  and fuzzy-scored against the drill's text.
- **Tests** with hints, timers, and scoring; demo videos and shorts
  generated by a MoviePy Space.

**Document** — a growing corpus, not a pile:
- Every drill carries **variety, region, speaker, provenance (source URL),
  license, and Latin romanization** alongside the three scripts.
- **👤 Accounts** (personal token, hashed at rest): isolated SRS schedules
  and contributor attribution.
- **📖 Corpus page**: search across all scripts, filter by variety, listen,
  and **verify** contributions (the review queue).
- **Export**: `/corpus/export` (JSON/CSV with full provenance) and
  `/corpus/flywheel?verified_only=true` — verified (audio, text) pairs ready
  to fine-tune the ASR/translation models. Per-recording consent is captured
  at creation; `private` items never leave.

## Architecture

| Part | Stack | Where |
|---|---|---|
| Frontend | React 19 + Vite + TypeScript + Capacitor | Vercel (web) / Android |
| Backend | FastAPI + SQLAlchemy | Render (Postgres) · local SQLite |
| ASR | Whisper (Docker FastAPI Space) | `huggingface-asr-space/` |
| Translation | Fine-tuned NLLB (Gradio Space) | `huggingface-translation-space/` |
| OCR | EasyOCR Latin+Arabic (Docker Space) | `huggingface-ocr-space/` |
| Video generation | MoviePy (Space) | `huggingface-space/` |
| Media | Cloudinary | all audio/image/video |

The backend orchestrates everything (`backend/main.py`); heavy AI work lives
on HuggingFace Spaces; media is vaulted to Cloudinary. New nullable columns
deploy automatically (lightweight schema sync at startup).

## Running locally

```powershell
# Backend (port 8000; SQLite drills.db)
cd backend
python -m venv venv; venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py

# Frontend (port 5173)
cd frontend
npm install
npm run dev        # build: npm run build · lint: npm run lint
```

Copy `backend/.env.example` → `.env` (Cloudinary, HuggingFace key + Space
URLs, optional `API_KEY`, `DEEPSEEK_API_KEY`) and `frontend/.env.example` →
`.env` (`VITE_API_URL`, optional `VITE_API_KEY`). The dev server targets a
local backend on the same host it was served from; production web builds
target the Render API.

## Key API groups

- `/drills/`, `/tests/` — CRUD + media upload/trim + TTS
- `/video-analysis/*` — `import-url`, `upload`, `analyze`, `align-lyrics`,
  `correct`, `ocr`, `translate`, `create-drills`, `auto-drills`, `job/{id}`
- `/reviews/*` — SRS: `due`, `{id}/grade`, `stats` (per user)
- `/pronunciation/check` — ASR-scored pronunciation feedback
- `/users/*` — `register`, `me` (send `X-User-Token`)
- `/corpus/*` — `search`, `export`, `flywheel`, `stats`
- `/drills/{id}/verify` — contribution review

Optional API-key gate: set `API_KEY` (backend) + `VITE_API_KEY` (frontend)
to require `X-API-Key` on all mutating requests.
